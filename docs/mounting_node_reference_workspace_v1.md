# Mounting Node Reference Workspace v1 — Confirmat

Українська назва: **Еталон монтажного вузла v1 — Конфірмат**.

Референсна сторінка: системний монтажний вузол **«Конфірмат 7×50»**, node 19.

Точка відліку: Git commit `d0eb35e0bae08118a3531df040b6bed895d10084` (`Complete confirmat mounting node reference workspace`).

## 1. Призначення

Це офіційний UI/UX-контракт для сторінок монтажних вузлів MP Furniture Platform.

Якщо в задачі без додаткового уточнення використано формулювання «еталон монтажного вузла», «еталонна сторінка», «як у Конфірмата», «Reference Workspace v1» або «Mounting Node Reference Workspace v1», мається на увазі саме цей еталон.

## 2. Що входить в еталон

Еталон фіксує не лише зовнішній вигляд, а весь підхід до побудови сторінки:

- стандартний App Shell;
- breadcrumbs і page header;
- компактну `WorkspacePage`;
- логічну ієрархію інформації;
- основну інформацію монтажного вузла;
- склад фурнітури;
- монтажні отвори;
- 3D монтажного вузла;
- 2D схему;
- вкладки 3D / 2D;
- zoom/pan для 2D;
- блок «Деталь та отвір»;
- схему розміщення монтажного вузла;
- компактні відступи та typography;
- кнопки й картки;
- selected/hovered states;
- технічну графіку;
- координатну систему;
- поведінку editor/detail mode.

## 3. Спільні компоненти та стилі

Наступні монтажні вузли повинні максимально перевикористовувати наявні компоненти та стилі, а не створювати дублікати. Поточні ключові точки еталона:

- `frontend/admin/src/components/processing/HolesMountingThreePreview.jsx`;
- `frontend/admin/src/components/processing/SchematicZoomSvg.jsx`;
- `frontend/admin/src/components/processing/MountingNodesPanelRefined.jsx`;
- `frontend/admin/src/App.jsx`;
- `frontend/admin/src/styles.css`;
- CSS-сімейства `mounting-node-*`, `holes-*`, `mounting-node-detail-tech-*`.

Це ключові точки на момент фіксації v1, а не незмінний і вичерпний список назавжди.

## 4. Технічна семантика 2D

- Through hole на видимій площині позначається звичайним суцільним контуром.
- Blind hole на видимій площині позначається основним контуром і тонким червоним штриховим кільцем, розташованим дуже близько до основного контуру.
- Прихований отвір або свердління, якого не видно з поточного виду, позначається синьою штриховою геометрією.
- Зелений колір використовується для UI selection/highlight, а не як технічне позначення типу отвору.
- Explanatory callouts використовують похилі або діагональні leader lines зі стрілками.
- Червоні розмірні лінії залишаються ортогональними технічними розмірами.

## 5. 3D і координатна система

Для `face_to_edge` координатний origin є семантичною точкою системи координат вузла, а не просто поверхнею деталі.

Для еталонного Confirmat горизонтальна панель має `Y=0` по центру своєї товщини. Візуальні осі, XYZ labels і orbit target повинні відповідати цьому origin.

Не можна змінювати координати отворів лише заради косметичного вирівнювання осей.

## 6. Деталь та отвір

Блок «Деталь та отвір» є основою майбутньої системи технічних креслень деталей:

- на деталь дивимося по її площині;
- площинний отвір показується як отвір на видимій поверхні;
- торцевий або прихований отвір показується як hidden geometry;
- проекція координат залежить від орієнтації конкретної деталі;
- це не декоративна схема, а CAD-подібне технічне представлення.

## 7. Правило для наступних монтажних вузлів

Наступний вузол після Confirmat — Minifix.

Під час реалізації Minifix не можна:

- копіювати всю сторінку в окремий великий компонент;
- дублювати CSS без необхідності;
- створювати новий паралельний дизайн.

Потрібно:

- використовувати Reference Workspace v1 як базову структуру;
- перевикористовувати спільні компоненти;
- перевикористовувати CSS-класи;
- розширювати компоненти через тип монтажного вузла, геометрію та дані;
- змінювати предметну логіку, кількість деталей, отвори та 3D-геометрію лише там, де це справді потрібно для Minifix.

## 8. Допустимі відхилення

Відхилення від Reference Workspace v1 допускаються, якщо:

- конкретний монтажний вузол фізично потребує іншої геометрії;
- потрібні додаткові деталі;
- потрібна інша кількість площин;
- потрібні інші типи або напрями отворів;
- користувач окремо погодив зміну UI/UX-еталона.

Не можна самовільно змінювати загальну систему оформлення лише тому, що новий вузол має іншу предметну логіку.

## 9. Versioning

Reference Workspace v1 прив'язаний до commit `d0eb35e0bae08118a3531df040b6bed895d10084`.

Якщо в майбутньому користувач явно затвердить новий глобальний еталон оформлення, створюється нова версія, наприклад `Mounting Node Reference Workspace v2`. Історичне значення v1 при цьому не переписується.

## 10. Зв'язок з архітектурною картою
